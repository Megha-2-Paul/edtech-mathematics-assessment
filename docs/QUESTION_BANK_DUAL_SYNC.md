# Question Bank Sync

The question bank now supports the workflow needed for the public teacher UI:

```
Public Render teacher UI
        |
        v
Aiven/Render MySQL (cloud source of truth)
        |
        | local pull
        v
Local MySQL
```

## Public workflow

Use the deployed teacher UI to:

1. Upload the extraction JSON.
2. Review/edit the extracted question.
3. Approve the question.
4. The approved canonical question is stored in the cloud database.

The public deployment does **not** try to connect to a MySQL server running on your laptop.

## Local sync

On the machine running the local MySQL database, keep this in the local `.env`:

```env
QUESTION_BANK_SYNC_DATABASE_URL=<cloud MySQL SQLAlchemy URL>
```

Never commit the credential.

After approving questions through the public UI, run:

```powershell
python scripts/sync_question_bank.py
```

The command:

- reads the cloud `questions` table;
- inserts new cloud questions into local MySQL;
- updates matching local questions;
- copies inactive status too, so deactivated cloud questions are reflected locally;
- leaves local-only question IDs untouched.

Restart the local Flask application after syncing so its in-memory question cache reloads.

## Existing local -> cloud support

The earlier dual-write code is still useful. When a question is approved through the local extraction UI with `sync_to_secondary=True`, it writes to cloud first and then local.

That path is retained as a safe fallback/authoring workflow.

The new normal workflow, however, is:

**Public UI -> cloud -> local pull.**

## Assets / images

Question records and their JSON content are synchronized by this command.

Source-PDF visual assets currently use the `question_assets.file_path` value generated by the extraction process. On Render that path can point to Render's local filesystem, which is not a reliable long-term shared storage location. Therefore this first cloud->local sync intentionally does **not** copy the binary asset files.

This is safe for text/MCQ questions without stored visual assets. For image/diagram questions, the next storage improvement should move source visuals to durable object storage (for example Cloudinary) and store the durable URL in `question_assets`. That will make the same visual available to both Render and local development.

## Scope

Only question-bank records are synchronized. Student attempts, evaluations, payments and other application data are not replicated.

The cloud database is the source of truth for questions created through the public teacher UI.
